# 💰 Money Result

เว็บแอปบันทึกยอดเงินการเล่นรายวัน (zero-sum) — คำนวณ Buy In, สรุปยอดสุทธิ,
ช่วยเกลี่ยยอดให้ลงตัวที่ 0 และมีหน้า Dashboard สรุปสถิติพร้อมจัดการรายชื่อผู้เล่น

ใช้ **Google Sheets เป็นฐานข้อมูล** ผ่าน **Google Apps Script** เป็น API
และ deploy เป็น static site บน **GitHub Pages**

## 🔧 ขั้นตอนที่ 1 — ตั้งค่า Google Sheets + Apps Script

### 1.1 สร้าง Spreadsheet

1. เปิด <https://sheets.new> สร้างไฟล์ใหม่
2. ตั้งชื่อไฟล์ เช่น `Money Result DB`

> **ไม่ต้องสร้างชีตหรือหัวตารางเอง** — สคริปต์จะสร้างให้อัตโนมัติในขั้นตอนถัดไป

### 1.2 วางโค้ด Backend

1. ในไฟล์ Sheet นั้น เลือกเมนู **ส่วนขยาย (Extensions) → Apps Script**
2. ลบโค้ดเดิมใน `Code.gs` ทิ้งทั้งหมด
3. คัดลอกเนื้อหาจากไฟล์ **`gas/Code.gs`** ในโปรเจกต์นี้มาวางแทน
4. กด **บันทึก** (ไอคอนแผ่นดิสก์ หรือ `Ctrl+S`)

### 1.3 รันฟังก์ชันติดตั้ง

1. ที่แถบด้านบนของ Apps Script เลือกฟังก์ชัน **`setup`** จาก dropdown
2. กด **Run**
3. ครั้งแรกจะขึ้นขออนุญาต ให้กดตามลำดับ:
   - **Review permissions** → เลือกบัญชี Google ของคุณ
   - หน้าจอขึ้นว่า *"Google hasn't verified this app"* → กด **Advanced**
   - → กด **Go to (ชื่อโปรเจกต์) (unsafe)** *(ปลอดภัย เพราะเป็นสคริปต์ของคุณเอง)*
   - → กด **Allow**
4. กลับไปดูที่ Spreadsheet จะเห็นชีตใหม่ 2 ชีตถูกสร้างขึ้น:

**ชีต `Players`**

| ID | Name | Active | CreatedAt |
|----|------|--------|-----------|

**ชีต `Records`**

| SessionID | Date | Player | BuyIn | Rebuy | TotalBuyIn | CashOut | Adjust | Net | CreatedAt |
|-----------|------|--------|-------|-------|------------|---------|--------|-----|-----------|

### 1.4 Deploy เป็น Web App

1. มุมขวาบนของ Apps Script กด **Deploy → New deployment**
2. กดไอคอนเฟือง ⚙️ ข้าง *Select type* → เลือก **Web app**
3. ตั้งค่าดังนี้ (**สำคัญมาก**):

   | ช่อง | ค่าที่ต้องเลือก |
   |------|----------------|
   | Description | อะไรก็ได้ เช่น `v1` |
   | **Execute as** | **Me (อีเมลของคุณ)** |
   | **Who has access** | **Anyone** |

   > ต้องเป็น **Anyone** เท่านั้น ถ้าเลือก *Anyone with Google account* เว็บจะเรียก API ไม่ได้

4. กด **Deploy** → คัดลอก **Web app URL** เก็บไว้

   หน้าตาประมาณนี้:
   ```
   https://script.google.com/macros/s/AKfycbxxxxxxxxxxxxxxxxxxxxxxxxxx/exec
   ```

> ⚠️ **ทุกครั้งที่แก้ `Code.gs`** ต้อง **Deploy → Manage deployments → ✏️ แก้ไข →
> Version: New version → Deploy** ไม่งั้นเว็บจะยังเรียกโค้ดเวอร์ชันเก่าอยู่

### 1.5 ใส่ URL ลงในเว็บ

แก้ไฟล์ `js/config.js` แล้ว push ขึ้น GitHub — **ที่นี่ที่เดียว**

```js
window.APP_CONFIG = {
  API_URL:   'https://script.google.com/macros/s/AKfycbxxxx.../exec',
  API_TOKEN: 'xxxxxxxxxxxxxxxxxxxxxx',   // ต้องตรงกับ CONFIG.API_TOKEN ใน gas/Code.gs
  ...
};
```

> 🔒 ปลายทางถูกล็อกไว้โดยตั้งใจ — **ผู้ใช้แก้ผ่านหน้าเว็บไม่ได้** (ไม่มีปุ่มตั้งค่า)
> ข้อดีคือผู้ใช้ใหม่เปิดลิงก์แล้วใช้ได้ทันที ไม่ต้องตั้งค่าอะไรเลย

### 1.6 เพิ่มรายชื่อผู้เล่น

เข้าหน้า **สรุปผล → จัดการผู้เล่น** → พิมพ์ชื่อ → กด **เพิ่ม**
รายชื่อจะไปโผล่ที่หน้าบันทึกยอดทันที

## 🚀 ขั้นตอนที่ 2 — Deploy ขึ้น GitHub Pages

### 2.1 สร้าง Repository และ push

```bash
cd "Money Result"

git init
git add .
git commit -m "Money Result — daily ledger web app"
git branch -M main
git remote add origin https://github.com/<ชื่อผู้ใช้>/money-result.git
git push -u origin main
```

> ถ้ายังไม่มี repo บน GitHub ให้สร้างที่ <https://github.com/new> (ตั้งเป็น Public
> หรือ Private ก็ได้ — Private ต้องใช้ GitHub Pro ถึงจะเปิด Pages ได้)

### 2.2 เปิด GitHub Pages

1. เข้า repo บน GitHub → แท็บ **Settings**
2. เมนูซ้าย → **Pages**
3. ตั้งค่า:
   - **Source**: `Deploy from a branch`
   - **Branch**: `main` / โฟลเดอร์ `/ (root)`
4. กด **Save**
5. รอ 1–2 นาที แล้วรีเฟรชหน้า จะได้ลิงก์:

   ```
   https://<ชื่อผู้ใช้>.github.io/money-result/
   ```

### 2.3 อัปเดตเว็บครั้งถัดไป

```bash
git add .
git commit -m "อัปเดต ..."
git push
```

GitHub Pages จะ build ใหม่เองภายในไม่กี่สิบวินาที

### 2.4 เพิ่มลงหน้าจอโฮมของ iPhone

แอปนี้ออกแบบมาให้ใช้บน iPhone เป็นหลัก แนะนำให้ติดตั้งลงหน้าจอโฮม:

1. เปิดลิงก์ GitHub Pages ด้วย **Safari** (ต้องเป็น Safari เท่านั้น — Chrome บน iOS ทำไม่ได้)
2. กดปุ่ม **แชร์** (สี่เหลี่ยมมีลูกศรชี้ขึ้น) ที่แถบล่าง
3. เลื่อนลงเลือก **เพิ่มไปยังหน้าจอโฮม (Add to Home Screen)**
4. กด **เพิ่ม**

จะได้ไอคอนแอปบนหน้าจอโฮม เปิดแล้วเต็มจอ ไม่มีแถบ URL ของ Safari มากินพื้นที่

## 📖 วิธีใช้งาน

### หน้า 1 — บันทึกยอดประจำวัน

1. **เลือกวันที่** (ค่าเริ่มต้นคือวันนี้) และใส่ **Buy In เริ่มต้น** ที่ทุกคนลงเท่ากัน
2. **เลือกผู้เข้าร่วม** โดยกดที่ชื่อ (กดซ้ำเพื่อเอาออก)
3. **เติมเงินระหว่างเกม** — ในการ์ดของแต่ละคน กดปุ่ม `+100` / `+200` / `+500`
   ถ้าจะเติมหลายครั้งพร้อมกัน ให้กดปุ่ม `−` / `+` ปรับจำนวนครั้งก่อน
   (เช่น ปรับเป็น `2` แล้วกด `+100` = เติม 200) หรือใช้ช่อง **จำนวนอื่น** ใส่เอง
   ทุกรายการที่เติมจะขึ้นเป็นป้ายให้กด `×` ลบได้ และจำนวนครั้งจะรีเซ็ตกลับเป็น 1 ทุกครั้ง
4. **ใส่เงินคงเหลือท้ายสุด** ของแต่ละคน — ยอดสุทธิจะคำนวณให้ทันที
5. **เกลี่ยยอด** — ถ้ายอดรวมยังไม่เป็น 0 แผงเกลี่ยยอดจะเด้งขึ้นมาเอง:
   - แตะที่ชื่อเพื่อเลือกคนที่จะนำมาเฉลี่ย
   - กด **เกลี่ยให้คนที่เลือก** ระบบจะแบ่งเท่า ๆ กัน เศษปัดไปคนแรก ๆ
   - แก้ตัวเลขในช่องไหนก็ได้เอง ขอแค่ผลรวมกลับมาเป็น 0
   - จะใส่ค่าติดลบให้กดปุ่ม **±** ข้างช่องนั้น
     (คีย์แพดตัวเลขของ iPhone ไม่มีปุ่มลบ จึงต้องใช้ปุ่มนี้แทน)
6. กด **บันทึก** (ปุ่มจะกดได้ก็ต่อเมื่อยอดรวมเป็น 0 เท่านั้น) แล้วยืนยันอีกครั้ง

> 🔒 **บันทึกแล้วแก้ไม่ได้** — ดูหัวข้อ [ข้อมูลบันทึกแล้วแก้ไม่ได้](#-ข้อมูลบันทึกแล้วแก้ไม่ได้-append-only) ด้านล่าง
> ข้อมูลที่กรอกค้างไว้จะถูกเก็บอัตโนมัติ ปิดหน้าไปแล้วกลับมากรอกต่อได้

### หน้า 2 — สรุปผล

- **ช่วงเวลา** — กดเลือกได้หลายเดือนพร้อมกัน หรือใช้ปุ่ม *ทั้งหมด* / *3 เดือน*
- **กราฟ + ตาราง** — ยอดสุทธิสะสมรายคน เรียงจากมากไปน้อย
  แตะที่แถบในกราฟเพื่อดูรายละเอียด (แตะซ้ำเพื่อปิด)
  ตัวเลขบนกราฟจะย่อเมื่อยอดถึงหลักหมื่น (เช่น `+12.3K`) — ดูค่าเต็มได้ที่ตารางสรุป
- **ประวัติรายวัน** — ดูย้อนหลังได้อย่างเดียว (แก้/ลบไม่ได้)
- **จัดการผู้เล่น** — เพิ่มชื่อใหม่ / เอาออกจากรายชื่อ (กด 🗑)
  การเอาออกเป็นแค่การซ่อนจากรายการที่เลือกได้ในหน้าบันทึกยอด
  **ประวัติการเล่นยังอยู่ครบและยังนับรวมในหน้าสรุปผลเหมือนเดิม**

## 🔒 ข้อมูลบันทึกแล้วแก้ไม่ได้ (append-only)

ชีต `Records` เป็นแบบ **เขียนเพิ่มได้อย่างเดียว** — ออกแบบให้เป็นหลักฐานที่ย้อนแก้ไม่ได้

| การกระทำ | ผ่านแอป |
|---|---|
| บันทึกวงของวันใหม่ | ✅ ได้ |
| บันทึกซ้ำวันที่เคยบันทึกแล้ว | ❌ ถูกปฏิเสธ |
| แก้ตัวเลขของวงที่บันทึกไปแล้ว | ❌ ไม่มีช่องทาง |
| ลบวงที่บันทึกไปแล้ว | ❌ ไม่มีช่องทาง |
| แก้ชื่อผู้เล่น | ❌ ปิดไว้ (เพราะต้องไปเขียนทับชื่อในประวัติ) |
| เอาผู้เล่นออกจากรายชื่อ | ✅ ได้ — เป็นแค่การซ่อน ไม่แตะประวัติ |

การบังคับใช้อยู่ที่ **ฝั่ง server** ไม่ใช่แค่ซ่อนปุ่ม:

- `gas/Code.gs` **ไม่มีคำสั่ง `deleteRow` อยู่ในไฟล์เลย** — ลบแถวไม่ได้แม้จะยิง API ตรง
- `saveSession_()` ตรวจว่าวันนั้นมีข้อมูลอยู่แล้วหรือยัง **ภายใน `LockService`**
  กันกรณีสองเครื่องกดบันทึกวันเดียวกันพร้อมกัน
- `deleteSession` / `renamePlayer` ตอบกลับว่าปิดใช้งานถาวร

### ถ้าบันทึกผิดจริง ๆ ต้องทำยังไง

**เข้าไปแก้ใน Google Sheet ด้วยมือ** — เปิดชีต `Records` หาแถวที่ผิด (ดูจากคอลัมน์ `Date`)
แล้วแก้หรือลบทั้งแถว จากนั้นกดปุ่ม ↻ ในหน้าสรุปผลเพื่อโหลดใหม่

> ถ้าลบทุกแถวของวันนั้นออกหมด จะกลับไปบันทึกวันนั้นผ่านแอปได้อีกครั้ง

## 🧮 กฎการเกลี่ยยอด

ยอดสุทธิของแต่ละคนคำนวณจาก

```
ยอดสุทธิ = เงินคงเหลือท้ายสุด − (Buy In เริ่มต้น + เงินที่เติมระหว่างเกม) + ค่าเกลี่ย
```

บันทึกได้ก็ต่อเมื่อ **ผลรวมยอดสุทธิของทุกคน = 0**

เวลากดเกลี่ย ระบบจะกระจายส่วนต่างตามกฎนี้:

- ยอดรวมเป็น **บวก (+)** → **หักเงิน** คนที่ถูกเลือกออก
- ยอดรวมเป็น **ลบ (−)** → **เพิ่มเงิน** ให้คนที่ถูกเลือก
- แบ่งเท่า ๆ กันก่อน ถ้าหารไม่ลงตัวให้ **ปัดเศษไปที่คนแรก ๆ ตามลำดับ**

ตัวอย่าง — ยอดรวมเป็น `+20` เลือกเกลี่ย 3 คน:

| คน | ค่าที่โดนหัก |
|----|------------|
| คนที่ 1 | −7 |
| คนที่ 2 | −7 |
| คนที่ 3 | −6 |

ลำดับ "คนแรก ๆ" คือลำดับเดียวกับที่แสดงในหน้าจอ (เรียงตามรายชื่อหลัก)
ไม่ขึ้นกับว่ากดเลือกใครก่อน — ผลลัพธ์จึงคาดเดาได้เสมอ

## 🛠 แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|-------|-----------------|
| `ยังไม่ได้ตั้งค่า API_URL ใน js/config.js` | ยังไม่ได้ใส่ URL — แก้ `js/config.js` แล้ว push ใหม่ |

| แก้ `Code.gs` แล้วไม่มีอะไรเปลี่ยน | ต้อง **Deploy → Manage deployments → ✏️ → New version → Deploy** |
| `ไม่รู้จักคำสั่ง (action)` | โค้ดใน Apps Script เป็นเวอร์ชันเก่า → Deploy version ใหม่ |
| `ยอดสุทธิรวมต้องเท่ากับ 0` | ยังเกลี่ยไม่ครบ — ดูตัวเลข *ส่วนต่าง* ที่แถบล่างจอ |
| `มีชื่อ "..." อยู่แล้ว` | ชื่อซ้ำ (ไม่สนตัวพิมพ์เล็ก/ใหญ่) — ใช้ชื่ออื่นหรือเช็กว่าเคยลบไปแล้ว |
| ข้อมูลไม่อัปเดตหลังบันทึก | กดปุ่ม ↻ ที่หน้าสรุปผลเพื่อโหลดใหม่ |
| เปิดหน้าเว็บแล้วขาว | เปิดผ่าน `file://` ไม่ได้ ต้องใช้ local server หรือ GitHub Pages |
| วันที่ในชีตเพี้ยนไปเป็นรูปแบบอื่น | รัน `setup()` อีกครั้ง เพื่อบังคับคอลัมน์ Date เป็น text |

## 🔒 ความปลอดภัย

Web App ตั้งเป็น *Anyone* (จำเป็น ไม่งั้นเว็บเรียก API ไม่ได้) จึงมีการตรวจ **token** กำกับไว้

```
js/config.js  ── API_TOKEN ──┐
                             ├── ต้องตรงกัน
gas/Code.gs   ── API_TOKEN ──┘
```

ทุก request จาก `js/api.js` จะแนบ `token` ไปด้วยอัตโนมัติผ่านฟังก์ชัน `withAuth()`
ฝั่ง `Code.gs` เรียก `checkToken_()` **ก่อน** `dispatch_()` — ถ้า token ไม่ตรง จะไม่มีคำสั่งไหนได้แตะ Sheet เลย

**กันอะไรได้:** บอทที่สแกนเจอ URL, ลิงก์ `/exec` ที่หลุดไปอยู่ใน log หรือแชท

**กันไม่ได้:** คนที่เปิด public repo นี้ หรือกด View Source ที่หน้าเว็บ — เพราะเป็น static site
ไฟล์ JS ทุกไฟล์ถูกส่งไปที่เบราว์เซอร์ผู้ใช้ จึงซ่อนความลับไว้ในนั้นไม่ได้

> คิดว่ามันคือ **กลอนประตู ไม่ใช่ตู้เซฟ** — ถ้าต้องการกันจริงจัง ต้องเปลี่ยน repo เป็น private

**ข้อควรรู้:** ระบบนี้ไม่มีบัญชีผู้ใช้ — **ใครก็ตามที่ได้ลิงก์เว็บไป มีสิทธิ์เท่ากันทั้งหมด**
รวมถึงลบข้อมูลทั้งวงและลบผู้เล่นได้ เหมาะกับใช้ในกลุ่มที่ไว้ใจกัน

**เปลี่ยน token:** แก้ทั้ง 2 ไฟล์ให้ตรงกัน → `cd gas && clasp push && clasp deploy` → `git push`
**ปิดการตรวจ:** ตั้ง `API_TOKEN: ''` ใน `gas/Code.gs`

### การแชร์ Google Sheet

การตั้งค่าแชร์ของ Sheet **ไม่มีผลกับการทำงานของแอป** เพราะ Apps Script เข้าถึงในนามเจ้าของไฟล์เสมอ
(`executeAs: USER_DEPLOYING`) เว็บไม่เคยคุยกับ Sheet โดยตรง

- ตั้ง **Restricted** → ปลอดภัยที่สุด แอปยังทำงานปกติ
- ตั้ง **Anyone with link / Viewer** → ได้ ใครมีลิงก์ Sheet อ่านข้อมูลดิบได้ แต่แก้ไม่ได้
- ❌ **อย่าตั้ง Anyone with link / Editor** → ใครก็ลบข้อมูลทิ้งได้ และยอดจะเพี้ยนโดยแอปไม่รู้ตัว

## 🔧 อัปเดตโค้ดฝั่ง Backend ด้วย clasp

โปรเจกต์นี้ผูกกับ Apps Script ผ่าน [clasp](https://github.com/google/clasp) แล้ว
แก้ `gas/Code.gs` เสร็จแล้วสั่ง:

```bash
cd gas
clasp push                                   # อัปโหลดโค้ด
clasp list-deployments                       # ดู deployment id ที่เว็บใช้อยู่
clasp redeploy <deploymentId> --description "อธิบายสั้น ๆ"
```

> ⚠️ **ห้ามใช้ `clasp deploy` เฉย ๆ** — คำสั่งนั้นสร้าง deployment **ใหม่พร้อม URL ใหม่**
> ทำให้ URL เดิมที่ฝังไว้ใน `js/config.js` ยังชี้ไปโค้ดเวอร์ชันเก่าอยู่ (เว็บจะเหมือนไม่อัปเดต)
> ต้องใช้ **`clasp redeploy <deploymentId>`** เพื่ออัปเดตทับตัวเดิม URL ถึงจะคงที่
>
> `deploymentId` คือส่วนที่อยู่ระหว่าง `/macros/s/` กับ `/exec` ใน `API_URL`

ครั้งแรกบนเครื่องใหม่ต้อง `npm i -g @google/clasp` และ `clasp login` ก่อน
และ `gas/.clasp.json` ไม่ได้อยู่ใน repo — สร้างใหม่ด้วย `clasp clone <scriptId>`
